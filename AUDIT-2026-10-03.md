# VoidMark 1.3.8 review

This audit fixes verified event-handling, Lua-scope, UI-state and transient-cache defects. The GitHub source was reviewed at commit `69d108f0adb06951bb0b0c12cd2c394f70d1f850` before applying these changes.

## Main fixes

- **Hunter deaths:** `RecordKill` now captures the intended local confirmation/Feign helpers and tables. The public Hunter helper now accepts normal method calls. Live Feign does not advance streak, persist a kill or play a kill effect; a confirmed real Hunter death does. The separate RunBack combat observer applies the same Feign gates.
- **Cooldowns:** repeated reports from local combat log and group observers are coalesced, and own addon-message echoes are ignored. Buff removals without a source GUID clear the active state. Cold Snap/Preparation reset cooldowns without erasing still-active effects. Active effects remain visible even with a ready cooldown. The Priest Shadow Protection name no longer collides with protection potions; actual potion spell IDs are still recognized.
- **UI and KOS:** repaired the late-local record heading and sync button; corrected two texture escape sequences. Custom KOS text is stored in the Other field. Secure rows run menu/modifier actions only on mouse release so one click does not toggle twice. Secure targeting attributes are still prepared outside combat.
- **Run-back rows:** expiry and capacity removal notify the list-pin cleanup after removing the active timer. Name lookup counts a player once when present in both the live list and saved player data, and removal only clears mappings owned by that timer.
- **Gear swapping:** disabling auto swapping cancels an already scheduled riding swap. A manual ground set queued in combat is preserved when combat ends.
- **Counters and alerts:** the first kill/pet/Sap immediately after startup is no longer mistaken for a repeat. Record statistics invalidate at weekly reset even without another kill. Remote Sap warnings ignore own echoes, accept group channels and throttle duplicate warnings from the same member.
- **Memory maintenance:** stale transient kill, pet, confirmation, Feign and share caches expire outside combat. Unselected cooldown records expire after one hour without observations. Saved player records, lifetime kills, KOS and other persistent history are not purged.
- **Version/commands:** TOC and runtime now agree on 1.3.8; `/voidmark` and `/vm` remain the public main commands. The legacy `/spy` alias is removed. Internal Spy names and SavedVariables remain compatible with existing data.

## Validation performed

- Compiled all 89 Lua files and all 31 XML event scripts; resolved every TOC/XML include; checked literal bundled texture/sound paths.
- Static scope analysis over first-party Lua code, followed by a manual review of remaining hits (intentional global/module imports).
- Executed the actual GankRepository, GankTracker, EnemyMoves, DamageRecords, RunBack, RideOrDie, List and MainWindow code with a mocked WoW API. Regression checks cover the changes above, including real repository kill writes and duplicate suppression, character-separated records, rank-specific bubble durations and shared lockouts, cache expiry, timer restore/expiry, KOS custom text and once-per-click utility actions.
- Loaded three supplied saved-data snapshots containing 7,514, 8,028 and 8,160 kill events. Each accepted exactly one simulated real death, rejected a simulated Feign and rejected duplicate credit. The uploaded files were never written or included in this commit.
- Reviewed the offline Windows sync/watchers statically. Their PowerShell/VBScript behavior was not executed in this Linux environment; these utilities were not changed.
- `git diff --check` passed.

Reproduce the repository checks from its root:

```sh
python3 tests/check_structure.py
luatex --luaonly tests/regression.lua
```

The harness tests Lua behavior, not Blizzard's secure execution or visual layout. The checks do not establish the cause of the earlier WoW/Discord crashes. The run-back graveyard/route model retains its existing data and its documented uncertainties.
